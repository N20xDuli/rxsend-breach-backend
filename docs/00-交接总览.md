## 一句话

一台能跑但**从未有玩家进入过**的 GMod 测试服；游戏模式是 `Breach`（SCP:SL 风格）的一个分支，
代码量 14.6 万行、阵营框架齐全，但**"模式"这一层基本是空壳** —— 设计上写了 8 个模式，
实际只有 1 个能跑。后续工作就是把这层补起来。

## 风险 Top 5

| # | 风险 | 影响 | 建议 |
|---|---|---|---|
| 1 | 玩家从未成功进入过 | 所有玩法验证都无意义 | 优先确认 UDP 30679 映射 + 客户端能否连入 |
| 2 | 出网 443 被封 | 创意工坊 / Steam 列表上报不可靠 | 内容全部走本地，`sv_downloadurl` 改自建 HTTP |
| 3 | 触发 `ww2tdm` 等模式即崩 | 玩家掉线 / 回合中断 | 上线前先补 `BREACH_ROLES.MINIGAMES` 或删除入口 |
| 4 | 数据盘仅余 7.3 GB | 无法扩容内容 | 可回收 `incoming/` 里 5.2 GB 旧归档 |
| 5 | 服务器无 git，源码即现网 | 误改即无法回滚 | 一律走 `staging/` + `apply.py` 管线 |

## 接手方的第一件事

按顺序做完这四步，才算真正"接上"：

1. **确认能连进去**（最优先，否则后面全是空转）
   ```bash
   ssh -p 30677 user@rdp.strynir.cloud
   systemctl status rxsend-server
   ```
   然后由客户端实际连接 `112.30.74.137:30679`，输密码进服。若进不去，先查 UDP 映射。

2. **拉仓库、跑一次全量校验**，确认拿到的和现网一致
   ```bash
   git clone https://github.com/N20xDuli/rxsend-breach-backend
   # 服务端生成当前哈希，与 docs/baseline.sha256 比对
   ```

3. **读懂装载链**（见 02 文档第一节），知道改哪个文件会被谁加载。

4. **读完 05 文档的阻塞项**，把该拍板的拍了，再动代码。
