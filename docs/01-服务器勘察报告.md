## 八、改代码的正确姿势（已建立的部署管线）

服务器上**没有 git 仓库**，源码即现网文件。历史交付走的是「带清单的暂存包」流程：

```
/srv/rxsend/staging/<name>/   ← 必须放在 /srv/rxsend/server 之外
  ├─ README.txt      操作步骤
  ├─ apply.py        check / apply / rollback
  ├─ manifest.json   每个文件的 old + new SHA256
  └─ payload.tar.gz
```

流程：`apply.py check`（只读预检，允许有玩家）→ `systemctl stop rxsend-server` →
`apply.py apply`（校验哈希、逐文件备份、原子替换保留 mode/UID/GID）→
`apply.py check --expect new` → 起服验证。回滚 `apply.py rollback --backup <dir>`。

已有两份历史包：`rx-feedback-2e7fd09`（30 改 + 5 删）、`rx-branding-9dee5d7`（15 改）。
基线记录在 `/srv/rxsend/deployment-evidence/release.json`（`game_functional_baseline: 3e9c0c9`）。

> ⚠️ 后续所有改动：**先在本地改 → 打 staging 包（带 manifest 哈希）→ 上传 → 按 README 走 apply.py**。
> 不要直接编辑现网文件，否则会破坏回滚链。

## 九、结论：要做的「后端」具体是什么

结合目标（实现具体阵营 + 模式玩法），缺口可归为 4 类工作：

1. **模式骨架**：为 `normalevent / hl2tdm / uiugoc / event / ny_event / furry_event`
   在 `ROUNDS` 里补齐 `setup / init / roundstart / postround / endcheck`（可参照 `normal`）。
2. **阵营角色表**：补齐 `BREACH_ROLES.MINIGAMES`（至少 roles[4..8]），或按新阵营拆成
   `sh_<faction>.lua` + `BREACH.<X>.Register()` 的独立模块。
3. **地图数据**：`mapconfigs/rxsend_site19-1.lua` 补 `SPAWN_*`（含 18 个缺失的 SCP 点），
   以及各模式的专属出生点 / 目标点。
4. **胜负与流程**：补 `normal.endcheck`（阵营胜负条件）、回合内目标（撤离 / 收容 / 防守）判定。
