## 一、装载链

GMod 的 gamemode 只有固定的两个入口，其余全靠 `shared.lua` 自己扫目录。

```
lua/autorun > gamemodes/rxsend_breach/gamemode/init.lua      ← 服务端入口
                              └─ include("shared.lua")
                                   ├─ GM:PlayerNoClip() = false
                                   ├─ include modules/sv_module.lua  (服务端框架)
                                   ├─ include modules/sh_module.lua  (共享框架)
                                   ├─ 扫 languages/*.lua 全部 include（**已排序**）
                                   ├─ 扫 modules/*.lua    按前缀分发（**未排序**）
                                   ├─ 扫 modules/anim_base/*.lua 同样规则
                                   └─ include mapconfigs/<当前地图>.lua
newMysql.initialize()                                        ← 服务端入口末尾
```

客户端入口 `cl_init.lua` 只做两件事：`include("shared.lua")` + 定义 ULib 权限查询辅助函数。

### 前缀规则（`shared.lua` 第 130–164 行）

| 前缀 | 服务端 | 客户端 |
|---|---|---|
| `cl_*` | 只 `AddCSLuaFile`，不执行 | `include` |
| `sv_*` | `include` | 完全不下发 |
| `sh_*` | `AddCSLuaFile` + `include` | `include` |
| `_*` | 跳过 | 跳过 |

文件名长度 ≤ 3 的也会被跳过。`sv_module.lua` / `sh_module.lua` / `cl_module.lua` / `cl_deployment_hud.lua` 已在前面手动加载，扫描时排除。

### ⚠️ 坑 1：模块加载顺序不可靠

```lua
local modules = file.Find( MODULES_PATH.."/*.lua", "LUA" )
for k, f in pairs( modules ) do          -- 没有 table.sort
```

语言包那段是**排了序**的（`table.sort(files)`），模块这段**没有**。
也就是说 `file.Find` 依赖底层 readdir 顺序，跨机器 / 跨文件系统可能不同。

**后果**：模块之间如果靠全局变量隐式依赖（A 定义了 `XXX`，B 直接用），行为不确定。
现有代码有大量这种隐式依赖（比如 `pos.AbilityCooldown`、`MODULES_PATH`、`ROLE_*` 常量表）。

**结论**：新增模块时，**不要假设别的模块已经加载过**。
需要共享的东西要么放在 `sh_module.lua`（必定先跑），要么用 `hook.Add` 延迟到运行时。

## 三、玩家生命周期

一个玩家从进服到变成某个阵营的角色，走这条链：

```
玩家进入
  └─ ply:SetupNormal()            重置模型/血量/武器/队伍到默认态
       └─ ply:ApplyRoleStats(role)    套用角色表里的全部字段
            ├─ team      → ply:SetGTeam()
            ├─ weapons   → BreachGive()
            ├─ ammo      → 弹药
            ├─ health / armor / walkspeed / runspeed / jumppower
            ├─ model / head / headgear / bodygroup0..7
            ├─ damage_modifiers → 按 HITGROUP_* 的伤害倍率
            └─ ability   → 技能（名称/冷却/描述/图标）
```

`ApplyRoleStats` 在 `sv_player.lua`，是所有角色属性的**唯一生效入口**。
改角色属性表现（比如加个新字段），就在这个函数里扩展。

## 五、五类扩展点

| 需求 | 改哪里 | 注意 |
|---|---|---|
| 加团队 / 改颜色 | `sh_gteams.lua` 末尾 `gteams.SetUp(index, name, color)` | 需要 `TEAM_*` 常量先定义 |

### 已有的「可插拔阵营」先例

`sh_roles_scp.lua` **文件末尾**：

```lua
if BREACH.Nu7        then BREACH.Nu7.RegisterRoles() end
if BREACH.HeavyArmor then BREACH.HeavyArmor.Apply() end
if BREACH.Alpha9     then BREACH.Alpha9.Register() end
if BREACH.Iris       then BREACH.Iris.Register() end
if BREACH.GOCTheory  then BREACH.GOCTheory.Register() end
```

对应模块：`sh_nu7.lua`、`sh_heavy_armor.lua`、`sh_alpha9.lua`、`sh_iris_animation.lua`、
`sh_theory_erasure_goc.lua`。**这就是加新阵营的推荐姿势** —— 独立文件 + 注册钩子，
不要去改 3,673 行的总表。

## 六、五个坑

### 坑 1：模块加载顺序不可靠
见第一节。别跨模块假设全局变量已就绪。

### 坑 2：`BREACH_ROLES` 的 key 命名是有约定的

支援阵营系统用这行取角色表：

```lua
return BREACH_ROLES[string.upper(supname)][string.lower(supname)].roles
```

所以 `BREACH_ROLES.NTF.ntf.roles`——**外层 key 必须等于内层 key 的大写**。
一旦写错（比如 `BREACH_ROLES.NTF.NTF`），拿到的是 `nil`，进服即崩。

特例硬编码在 `sv_module.lua:3288`：
`"FBI"` / `"FBIAgents"` → `BREACH_ROLES.FBI_AGENTS.fbi_agents.roles`；
`"FBI_SHTURM"` → `BREACH_ROLES.FBI.fbi.roles`。

### 坑 3：`BREACH_ROLES.MINIGAMES` 索引越界

当前只定义了 `roles[1..3]`（Nazi / USA / ArenaParticipant），
但 `Setuphl2` 用 `roles[4]`、`SetupCTF` 用 `roles[3]` 和 `roles[4]`。
`roles[4]` 是 `nil`，`ApplyRoleStats(nil)` 直接报错。

### 坑 4：地图配置文件缺失 = 启动失败

```lua
if file.Exists( MAP_CONFIG_PATH .. "/" .. game.GetMap() .. ".lua", "LUA" ) then ...
else error( "Unsupported map " .. game.GetMap() .. "!" ) end
```

换地图必须先加 `mapconfigs/<地图>.lua`，否则整服起不来。

### 坑 5：`cl_*` 文件必须能被客户端拿到

新加 `cl_*.lua` 时，`shared.lua` 的扫描会自动 `AddCSLuaFile`，**但**如果文件放在子目录
（`modules/scp173/`、`modules/anim_base/` 之外的其他新目录），扫描逻辑不会覆盖，需要手动 `AddCSLuaFile`。
