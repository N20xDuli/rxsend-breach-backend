## 三、仓库工作流

```
克隆    git clone https://github.com/N20xDuli/rxsend-breach-backend
分支    git checkout -b feat/<你的改动>
提交    小步提交，说明改了什么、为什么
审查    git diff main...HEAD  → 确认没有误改资源路径 / 没有夹带密码
```

## 四、部署管线（`staging` + `apply.py`）

服务器上没有 git，源码即现网。历史所有交付都走这条管线。

### 包结构

```
/srv/rxsend/staging/<name>/        ← 必须放在 /srv/rxsend/server 之外
├── README.txt                     操作步骤（给人看）
├── apply.py                       校验 / 应用 / 回滚
├── manifest.json                  每个文件 old + new 的 SHA256
└── payload.tar.gz                 实际文件
```

### 标准流程

```bash
# 1. 只读预检（此时可以有玩家在线，安全）
sudo python3 apply.py check

# 2. 正常停服
sudo systemctl stop rxsend-server

# 3. 应用（校验 old-hash → 逐文件备份 → 原子替换）
sudo python3 apply.py apply
#    输出一个 /srv/rxsend/backups/<name>-<timestamp>/ 目录

# 4. 校验新状态
sudo python3 apply.py check --expect new

# 5. 起服 + 冷启动验证
sudo systemctl start rxsend-server
journalctl -u rxsend-server -n 100 --no-pager
```

### `apply.py` 会拒绝的情况

- 符号链接、路径穿越、未知归档条目
- `old-hash` 与现网不符（说明有人绕过管线改过文件）
- 服务进程仍持有实例锁
- 归档里有 `manifest.json` 未声明的文件

替换时保留原文件的 `mode` / `UID` / `GID`；异常时按已知 old/new 哈希自动回滚。
它**不会**启动或停止服务——那是你的操作。

### 回滚

```bash
sudo systemctl stop rxsend-server
sudo python3 apply.py rollback --backup /srv/rxsend/backups/<printed-name>
sudo python3 apply.py check
sudo systemctl start rxsend-server
```

> 源码备份只是源码。**不包含**玩家数据 / 资源文件。
> 玩家数据（`garrysmod/data`、`sv.db`）由 `backup-restore-check.py` 那套单独处理。

## 五、交付前检查清单

每次发版前逐条打勾：

- [ ] `git diff` 审查完，没有意外改动
- [ ] 没有夹带 `rcon_password` / `sv_password` / 私钥
- [ ] 新增/删除的文件都在 `manifest.json` 里声明了
- [ ] 新增 `cl_*.lua` 已确认会被 `AddCSLuaFile` 下发（子目录尤其注意）
- [ ] 改动涉及的 convar / net 字符串两端一致
- [ ] `mapconfigs` 没有被误删（缺了整服起不来）
- [ ] 服务端能冷启动，`journalctl` 无 Lua 报错
- [ ] 进服实测：能出生、能选支援、能打、能结束回合
- [ ] 动过资源文件的话，重新生成一份 `inventory/` 快照
- [ ] 记录本次 `release.json` 风格的基线（commit + 内容哈希）

验证编译：`data/rxsend/deployment_acceptance.json` 里 `compile.checked` / `compile.errors`
是既有口径，目标是 `errors: []`。

## 六、资源清单工具

不是备份，只负责发现变化。详见 [`inventory/README.md`](../inventory/README.md)。

```bash
# 服务器上生成（只读，20 秒 / 16.6 GiB）
sudo python3 tools/rx_inventory.py --root /srv/rxsend/server \
     --out inventory/server-$(date +%F).tsv --summary

# 对比两个时间点
python3 tools/rx_inventory_diff.py \
    inventory/server-2026-11-06.tsv inventory/server-2026-12-01.tsv
```

输出 `ADDED` / `REMOVED` / `MODIFIED` / `MOVED` / `TOUCHED`。
`MOVED` 是"某个文件被挪到哪去了"（按 sha256 配对）。

> Windows PowerShell 里跑要先 `chcp 65001`，否则中文乱码（终端代码页问题，不是文件问题）。

## 七、禁止事项

| ❌ 不要 | 原因 |
|---|---|
| 直接在 `/srv/rxsend/server` 里 `vim` 改文件 | 破坏回滚链，下次 `apply.py` 的 old-hash 对不上 |
| 直接 `kill` 游戏进程 | 用 `systemctl stop`，让 `ExecStop` 走优雅停机（SIGINT） |
| 把密码 / 私钥提交进 git | 一旦进了历史就算泄漏 |
| 在 `data/` 里手工删表 | sqlite 结构由代码建，删了会丢玩家数据 |
| 换地图不加 `mapconfigs/<地图>.lua` | `shared.lua` 会直接 `error()`，整服起不来 |
| 把 `staging/` 放进 `server/` 目录 | `apply.py` 假定它在安装目录之外 |
| 假设模块加载顺序固定 | `file.Find` 结果未排序，见 02 文档 |

